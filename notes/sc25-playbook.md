## 一、游戏机制全谱(源码破译)

**主题:画符施法的地牢逃脱。过关条件 = 玩家精灵(pluyoo)走进出口精灵(exydhv)。**
画布只是施法工具,与过关判定无关。

| 咒语 | 3×3 图案(T=亮) | 效果 |
|---|---|---|
| fibcey | 中列竖线 (0,1)(1,1)(2,1) | **喷火**:火球沿"最后一次按的方向键"方向飞出,打中 `tagsmh` → 它和**全部** `dosorb`(挡路石)一起消失;`seofsw-tagsmh`/`seofsw-dosorb` 是平行的第二套 |
| sieesc_chwjgc | 菱形 (0,1)(1,0)(1,2)(2,1) | **变身**:scale 1↔2 切换。变大需要周围有空间,不够则闪烁失败;缩小总是成功 |
| tevyeq | 左上角形 (0,0)(0,1)(1,1) | **传送**:传到当前激活的标记处。scale2 用 `tevyeq-tagsmh` 标记组、scale1 用 `smzaik-` 组;每施放一次**轮转**到组内下一个标记;激活标记有指示物(`acyylh-tevyeq-inkpfx`)= 像素可见 |

机制细节:
- 画布 3×3,九个格子点击坐标 x∈{25,30,35} × y∈{50,55,60},点一下切换亮灭,每击计 1 步
- 每关 `efvw` 数据 = 必修咒语清单;**画非必修图案毫无反应**(匹配函数只认清单内的)
- 每关 `slfh` 数据 = 动作预算(右侧步数条),超了就 GAME_OVER;吃 `enjehv-pahtoz`(彩点)回 10 步
- 图案凑齐的**那一次点击**会在同一次引擎调用里把施法+火球/传送/变身动画一口气结算完
  (返回帧 layers=16),**不吃后续动作**
- 触到出口后还有 2 帧走出动画,真机上要再补 1-3 个动作才看到 level 翻转
- 三种图案的绘制中间态互不为前缀,不会误触发(竖线↔菱形↔角形两两验证过)

## 三、当年黑盒结论对账(哪些对了、哪些错了、为什么)

| 当年结论 | 对账 |
|---|---|
| "画布是二值的" | ✅ 对(每格亮/灭) |
| "计数器是步数条,与过关无关" | ✅ 对(动作预算 slfh;"与过关无关"半对——超了会输) |
| "画布(2⁹)×方块位置(30) 55188 状态穷尽无解" | ✅ 穷尽本身没错,但**赢的维度(玩家↔出口)不在这个空间里**;且 512 构型里只有必修图案有反应,绝大多数是死水 |
| "过关条件不在任何可观测维度" | ⚠️ 半对:火焰方向=最后按的方向键,确实只有玩家旋转 2px 的微弱提示;但主链(走到出口)**完全可观测**,被"画布才是主角"的先入之见挡住了 |
| "右边两个小方框在提示什么" | ✅ 问对了:就是必修咒语的图案提示面板 |
| "某操作要连按两次才生效"(滞后) | ✅ 对,perform_action 注入、下次结算,是引擎规则 |
| "深搜 6 层/随机 16 万步一无所获" | 三下正确格子的组合概率本来就低;且当年把"施法后画面剧变"当成噪声分支 |

**一句话病根:把"什么在变"(画布/方块/计数器)当成了全部状态,而赢在"什么能动去哪里"。**
帧 diff 看得见变化,看不见**目标结构**——这正是 harness "先补看懂"路线要解决的问题。

## 四、方法论沉淀(可迁移)

1. **白盒的正确姿势 = 源码定拓扑,实验定参数。** 攻击脚本(attack_sc25_l3/l5/l6.py)
   不硬编码任何坐标:火位/走位全部在克隆体上"枚举可达状态 × peek 试射"实验得出。
   源码告诉你谁挡谁、什么清什么;碰撞、步长、传送落点仍由真机说了算。
   (直接抄源码坐标写死序列 = 一个 off-by-one 就全盘崩,还学不到可迁移的东西)
2. **步数条必须从指纹里掩掉。** 它每步变一格 → 同一局面经不同步数到达永远去重
   不了,图搜索退化成分层树(L4 盲搜 5000 状态爆掉的主因之一)。
3. **盲搜不够时先别加预算,手推一条解看它到底多深。** L4 手推暴露病灶是**相位**
   (缺变身,物理上进不了火线走廊),加十倍预算也搜不出来。
4. **分段混合法 > 端到端盲搜**:相位序列(缩/传/火/变/传/走)人定,每段内用
   BFS/试射实验自动化。L5 一次成,L6 一次成。
5. **WIN 态后再喂动作返回空帧**——收尾判定要用 state,不要靠"再走一步看看"。

## 五、对 harness 泛化线的启示(黑盒要能解 sc25 需要什么)

按今天的地面真值倒推,一个黑盒 agent 要解开 sc25 至少需要:
- **宏效果发现**:能把"三次点击→场景剧变"识别为一个宏动作(单击 diff 全是小变化,
  凑齐图案才有大效果 —— 现有 discover 只做单动作 diff,看不见组合效果)
- **隐藏状态假设**:h 无法解释时,把"最近动作历史"纳入状态候选(朝向=最后方向键)
- **关系型目标**:"可动实体 → 某静态实体"的接近性(玩家→出口),而不是画布构型
- sc25 六关现在是第五套满分在案解,harness 每个改进都多了一局可对照回归

—— 以上三条与 ls20 L2 的结论(表征墙、关系型目标、搜索地形)互相印证。
