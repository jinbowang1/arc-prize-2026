# ARC-AGI-3 攻关流水线 (ls20 五关实战提炼, 2026-08-07)

面向正式比赛的可复用方法。每一条都有实测出处, 不写未验证的推测。

## 一、状态抽象:先把画面压成几个数

原始帧 64×64×16色 无法直接当状态。ls20 的语义状态是四元组:

```
(格子, 形状, 颜色, 能量)
```

- 格子 = 玩家 5×5 方块左上角(全图约 60 个可站格)
- 形状 = 左下面板 3×3 位掩码(**每格 2×2 像素**)
- 颜色 = 面板的颜色
- 能量 = 底部能量条像素计数

**这一步决定生死**: 用整帧像素当搜索指纹, 因为能量条每步递减 + 地图有巡逻体, 同一位置在不同时刻永不相等, 去重失效 → BFS 退化成穷举(实测内存吃到 4GB, 深度 40 未解)。换语义态后状态空间从天文数字压到 2~20 万, 搜索必然收敛。

## 二、目标识别:锁上写着答案

**锁房 7×7 显示框, 正中 3×3、每格 1 像素 = 过关要求的形状+颜色。**
左下面板 6×6、每格 2×2 像素 = 当前形状+颜色。两套编码分辨率不同, 读混就全错。

L1-L5 五关验证零例外(通关瞬间的形状颜色 == 该关开局锁上的显示)。

**过关条件 = 形状 AND 颜色 都匹配。** L1-L4 颜色恒为 9 所以这一维长期隐形, L5 才暴露。

⚠️ 读锁要在钥匙远离时读——贴近时钥匙会压住显示框边框, 检测器直接找不到。

## 三、模型学习:走路记账, 不训练

在真模拟器里连续行走采样(约 700 步/秒, 不深拷贝), 记录
`(格子, 形状, 颜色, 动作) → (新格子, 新形状, 新颜色, 能量变化)`。
探索策略: 优先选当前状态下试得最少的动作。

**泛化是关键一步**: 实测同一格在不同形状下四向落点完全一致 ⇒ 移动与形状无关, 于是把"按(格,形状)记"的碎图压成**纯格级转移表**(ls20 L5: 240 条, **零分歧**)。不做这步, 图碎得没法规划。

机关规律尽量写成**规则**而非查表(旋转用 `new[i][j]=old[2-j][i]`, 调色用颜色环), 查表太稀疏、组合一多就断链。

## 四、执行:分岔触发式重规划

三种执行方式实测对比:

| 方式 | 结果 |
| --- | --- |
| 开环(一次算完跑到底) | 机关格上必错 |
| 每步重规划 | 退化成随机游走 |
| **只在预测与实测分岔时重规划** | **有效**, 且分岔点直接暴露隐藏规则 |

第三种在 L5 上一次抓到"旋转器是移动的巡逻体、踩到它当前格才生效"。**一个反例定位一条隐藏规律。**

模型对**会移动的机关**预测不可靠。这类地方要么真机贪心, 要么整段改用真模拟器搜索。

## 五、资源约束:比规则更容易翻车的地方

L6 的教训全部来自资源调度, 不是理解:

- **补给是一次性的**(踩过永久失效) ⇒ 全关预算固定, 贪心"配一维跑一趟"必崩, 必须整体优化
- **死亡会重置形状和颜色** ⇒ 中途饿死等于前功尽弃, 宁可绕路补给也不能冒险
- 规划器默认优化**步数**而非能量, 会抄近路把油耗光 ⇒ 加"到达时能量下限"约束逼它绕路吃补给
- 补给点要按**规划器算的真实代价**挑, 不能按直线距离

## 五点五、搜索的启发式必须有梯度(L6 定案关键)

L6 末段真机搜索两版对比, 同一份代码只换 `h`:

| 启发式 | 结果 |
| --- | --- |
| 格距 + 形状不对罚6 + 颜色不对罚4 | 2 万次扩展, h 在 11~24 反复横跳, 未解 |
| **离线模型上到目标的真实剩余步数** | **6 秒解出**, h 从 44 单调降到 0 |

常数罚项没有梯度——"差一次旋转"和"差三次旋转加换族"同分, 最佳优先立刻退化成广度搜索。

**做法**: 在离线转移图上枚举可达的 `(格,形状,颜色)`(L6: 6196 态), 建反图, 从目标反向 BFS 得精确距离表。它忽略能量所以是下界(可采纳), 真机只在移动机关处偏离。
配两条剪枝: **饿死剪枝**(能量既够不到目标也够不到任一补给就砍)、**能量分档去重**(`能量//4`)。

一句话: **模型不用来执行, 用来当导航**。真机负责"走得通不通", 离线模型负责"该往哪走"——这比两者各自单干都强。

**模型太稀疏时, 直接拿真机当模型。** L7 的离线模型只有 282 条转移、只发现 2 个机关格, 不够规划。
但 `clone`+`raw` 的试探不消耗真实进度, 所以可以在真模拟器上直接做 BFS: 状态取 `(格,形状,颜色)`,
按**"到达时的最高能量"支配剪枝**(同一状态用更少能量到达的分支直接砍)。
边搜边建模, 找到的第一个解即最短且天然验证过。实测约 100 次扩展/秒, 队列稳定在几百, 不爆炸。
⚠️ 补给一次性会让"高能量支配低能量"不严格(高能量可能意味着补给已消耗), 是**为速度换来的可能漏解**, 要心里有数。

## 六、通用陷阱(每条都栽过)

1. **两个事件共享同一表面特征时, 别用该特征区分**。死亡和捡补给都让能量上升 → 必须看位置(死亡传送回起点, 捡补给正常移动一格)。
2. **学习器会把环境现象误记成机制**。关卡起点因为是死亡重生点(传送+回满), 被误记成"补给点", 导致代码一直往不存在的补给跑。
3. **打印 diff 时的 top-N 截断会掩盖第二个移动体**, 据此得出的结论全错。
4. **对象汤式引擎不能做部分快照**。camera/interface 与 game 有交叉引用, 部分复制必致状态泄漏; 只能整对象单 memo 深拷贝。验证分叉回滚要用"存档→走岔路→读档→续走 vs 一路直通"逐帧比对。
5. **核账脚本自身会重复计数**。L5 解合并进主档后, 计分脚本又追加一次, 总步数虚高 29% 而其他数字全部合理。
6. **拼接分段解时的边界重复**。L6 搜索里 `leg1` 是在执行完穿锁动作**之后**取的快照, 已含那一步, 拼接时又补了一次 `[2]`——搜索进程内报"通关", 全新环境重放却在中途饿死。
   **搜索内通关 ≠ 解可复现**: 分段解必须在全新环境上整条重放验证, 这是唯一算数的判据。

## 七、计分要点(官方文档 + scorecard 实测)

- `level_score = (人类基准步数 / AI步数)²`, 单关封顶 **1.15**
- 游戏得分 = 按关卡序号加权平均, **未通关的关直接锁死上限**(通 5/7 → 上限 15/28 = 53.57%)
- 总分 = 各游戏得分平均, **0~100%**; 不碰的游戏计 0
- **只有改变环境的动作计数**, 推理和工具调用免费 ⇒ 每步可以烧任意算力
- **重置不清账**, RESET 自身还吃 1 步 ⇒ 主动学习效率是唯一胜负手

## 七点五、分段求解: 把一次深指数拆成两次浅指数

L7 单段 BFS 要摸到深度 60+ 才可能通关, 太贵。拆成两段后**第一个候选就通了**:

- 阶段1: BFS 到任意格上的 `(目标形状, 目标颜色)` —— 深度 42 命中
- 阶段2: 从该状态继续 BFS 到通关, **丢弃任何改变形状或颜色的转移**(踩机关就前功尽弃)
- 阶段2 走不通就回阶段1 取下一个候选

阶段2 只扩展 342 次就结束——因为"形状颜色已锁死"把分支因子从 4 砍到接近 1, 退化成纯导航。
**先把配置维度配好、再把它冻住去导航**, 比让搜索同时优化位置和配置便宜一个数量级。

L7 换了地图主题(梯形透视场地), 但机制未变: 仍是 5 格步长网格、每步耗 2 能量、左下角形状颜色面板照常工作。
**新情况是视口会滚动, 开局画面只是地图一角。** 开局用 `find_locks` 扫不到任何锁, 不是编码变了, 而是锁不在当前视野里——走到 (40,19) 附近才读到 `色8 + 形状413`。
教训: **"扫不到目标"要先排除视野问题, 再怀疑编码规则。**

## 九、尚未自动化的部分(比赛真正的题)

本次所有关键发现——颜色维度、锁的编码规则、移动的旋转器、锁的永久开启、补给的一次性、L7 的视口滚动——**都是人工推理得出的**。比赛要求这些必须由程序在断网的开源小模型上自动完成, 且每步试探都计入分母。这才是榜首停在 1.86% 的真正原因。

不过有一条经验是可以直接迁进自动 harness 的: **判断"搜不出来"是深度不够还是机制没摸清, 不要靠加深搜索去试。**
L7 盲搜到深度 48 只长出 24 种形状且看不到目标, 我一度判定目标不可达; 改跑一个只问"形状可达集有多大、机关映射是什么"的勘探脚本, 才看到 413 就在深度 41、由 245 在 (15,54) 变来——盲搜方向本来是对的。
**一个只回答"机制是什么"的诊断跑, 比多搜十层都值钱。**
