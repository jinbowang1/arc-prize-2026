## 一、游戏结构与逐关机制

蓝图填色谜题:画面是色块格阵(格间距 8px,块 6×6),嵌着若干 6×6 **花纹块**。
**每个花纹的 3×3 图案是它周围 3×3 邻域的目标蓝图**。没有提交键,达成即过关。

| 关 | 新机制 | 我方/人类 |
| --- | --- | --- |
| L1 | 四宫格,蓝图=宫的 9/8 分布图 | 4/43 |
| L2 | 两花纹共管重叠邻域 | 7/12 |
| L3 | **中心色语义**:花纹中心色声明 `.` 位的目标色 | 14/23 |
| L4 | **三态环**(9→8→C),右上角 HUD 即色环图例 | 21/28 |
| L5 | **开关块**(6色格纹):点击批量翻转;先拨开关再补普通格 | 21/65 |
| L6 | **lights-out**:点击翻 self+up;128 击 GAME_OVER 上限 | 19/37 |

蓝图标记语义(逐关定标):`0`(黑)位 → 中心色,`2` 位 → 另一色,`3` 位 →
"该方向无格"(L5 起出现,8 个花纹的 3 位全部与真实空位吻合,零例外)。
点击次数 = 色环上从当前色到目标色的距离。

## 二、L6 的三个硬发现

### 1. 隐藏动作预算:第 128 击 = GAME_OVER

第 127 击一切正常,第 128 击 state 翻 GAME_OVER,再往后 levels_completed
读出 0、帧全空。**这不是引擎 bug,是每关动作上限**。它先以"61 万动作/秒的
遍历 7 秒跑完全空"的假象出现——其实第 128 击后一直在打一具尸体。
**动作速率异常快,先怀疑游戏已死,再怀疑引擎。**

### 2. 过关判定是路径依赖的

全态遍历找到过关态后,用最短点击集(11 击)复现**同一个终态,却不过关**;
而格雷码路径(19 击,先经过某中间态)就过。同终态、不同路径、不同结果——
判定读取的不只是画面色态。具体机制未破译(19 击已触封顶,停止了逆向),
但这条教训直接否定了"过关条件 = 静态谓词"的默认假设,值得写进 harness:
**枚举"态"失败时,改枚举"路径"。**

### 3. 格雷码全态遍历:每步一击扫完 2²²

lights-out 的 22 个点击向量在 GF(2) 上线性无关(下三角)→ 在"点击坐标系"
走二进制反射格雷码,**每步恰好一次点击,路过全部 420 万个态各一次,零克隆**。
判定每动作后都检查,所以只要过关条件与态(或路径)有关,遍历必命中。
配合 128 击预算改成分段版(每段 clone 一次:先 ≤22 击拨到段首态,再走 100 步),
4 分钟扫完全空间,在 110 万态处命中。

## 三、可迁移的心得

1. **click 游戏的真实分支因子是语义对象数,不是坐标数**。4096 个坐标塌缩成
   ~20 个连通块;块内点哪都一样。感知层先做对象化,搜索层才有意义。

2. **连通块检测会系统性漏掉"杂色块"**。L5 的开关块(格纹,单色碎片 <9px)
   两次逃过 blocks() 探测——第一次让我误判"蓝图对不可编辑格提了要求",
   第二次发现它是全关最关键的机关。**"探测不到"和"不存在"是两回事,
   蓝图指向哪里就该去点哪里。**

3. **"零画面反应"≠"无效点击"**。L1 的错误点击有闪烁,L6 的点击花纹零反应
   ——反馈风格每关都会变,不能拿上一关的反馈分类学套下一关。

4. **假设烧完之前,先把兜底穷举的可行性算一遍**。L6 我在 7 个目标假设
   (蓝图正/反、点击图、计数型、对称/反对称、变换枚举、多中心汉明球)上
   花了约 7.5 万次态验证,而全态遍历只要 4 分钟。**当单次验证便宜且判定
   每步都查时,"聪明假设"的期望成本可能高于暴力扫全集。**

5. **穷举实验自身要先验证执行层**。第一版格雷码 7 秒"扫完"420 万态,
   结论差点被当真——速度反常是唯一的破绽。凡是速率好得不像话的实验,
   先抽查中间效果(帧非空、状态在推进)再信结论。
