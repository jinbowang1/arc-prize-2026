### 1st: Tufa Labs "The Duck" — 1.21%
- 仓: `reference/duck-harness/` (已 clone), 写作: https://tufalabs.ai/research/duck-harness/, Kaggle 帖 717133
- **范式 = agent 写代码**: 游戏状态编码成 Python 变量, 模型在一个 ephemeral Python REPL 里写小段代码检查棋盘、调 `action(...)` 执行真实动作
- 模型: **Qwen 3.6 27B FP8 本地 vLLM**(Kaggle 断网, 靠 wheelhouse dataset 打包 vLLM+权重)
- 感知三通道: `current_frame.segmentation`(连通域/对象哈希/包含/邻接, **首选**) + `current_frame.ascii`(小范围核对) + 渲染图像; **原始数字网格刻意不给**
- 上下文: "infinite play via eviction" — 持续弹出最老消息, 只保系统提示+近期历史
- 关键教训: **手工工具反而伤模型, 让它即兴发挥更好**; 30s/次工具超时
- 工程资产: 完整本地评测框架 TAAF + `make significance`(配对 bootstrap, P(delta>0)≥0.90 才算超过基线) + 竞赛模拟器 `SIMULATE_COMPETITION_ARCADE=true` + Kaggle 打包流水线

### 2nd: Reki — VLM 策略
- 帧渲染成带标注图像 → 本地 **Gemma-4-31B** → 返回 JSON{变化描述, 计划, 1-4个动作}

- numpy 点击启发式: 优先小而稀有颜色的形状; "Dead-signature" 机制关卡中途停止点击无效对象类型

### 3rd: forge — 同为 Gemma-4-31B VLM JSON 策略
- 可配置框架: 候选动作生成 + arbiter 打分 + 不确定时保守动作

## 二、Preview Challenge 3rd: just-explore (零 LLM!)
- 仓: `reference/arc-agi-3-just-explore/` (已 clone, MIT), 论文 arXiv:2512.24156 (AAAI 2026 workshop)
- 纯**图探索**: Frame Processor(连通域分割+状态栏检测掩蔽+点击优先级五档+帧哈希) + Level Graph Explorer(节点=帧哈希, 边=动作, frontier 队列系统性穷举, 按优先级组顺序试)
- 成绩: 私榜 12/25 关(修 graph-reset bug 后中位 17 关, 仅比当届第 1 少 1 关)
- 弱点自述: 状态栏长得不一样就退化成随机; 大状态空间(ft09 L3-4)不可解; 非确定性/部分可观测出问题
- 作者指的下一步: 学习简单世界模型(帧+动作→下一帧)提高样本效率

## 三、计分与竞赛模式 (设计 harness 的硬约束)
- **RHAE**: level_score = (人类基准步数 / AI 步数)², 封顶 1.15×; 游戏内按关卡序号加权(后关权重大); 总分=各游戏平均
- **只有改变环境的 action 计数, 推理/工具调用/重试全部免费** → 每步可以烧任意多的算力
- 人类基准 = 首次玩家的 upper median; **toolkit 的 baseline_actions 就是逐关基准, 本地可精确算分**
- 竞赛模式(Kaggle 强制): 断网只能开源权重; 每个环境只能 `make` 一次; **只允许 Level Reset, Game Reset 会变成 Level Reset**; 只能开一张 scorecard 且中途看不到分; **按全部环境计分**(不碰的游戏=0)
- 私榜 = 未见过的游戏 → 智能必须泛化, 不能 per-game 调参

## 五、开放问题 (下一步实验验证)
1. **Level Reset 后动作计数是否清零?** 若不清零(大概率), 探索烧掉的每一步都永久计入 RHAE 分母 → 主动学习效率是唯一胜负手; 若清零则"先探索→reset→打最短路"是超级漏洞, 需实测
2. Kaggle 硬件配额(GPU 型号/时长)与 vLLM 27B FP8 的吞吐 → 决定每 action 能烧多少 token
3. ft09 无 tag、大状态空间 → 图探索的不可解游戏在 25 个里占比多少
