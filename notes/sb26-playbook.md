## 一、靶子怎么选的

按仓库既有的盲测规矩: **只看元数据, 不看内容**。sb26 是 `blind_sc25.py`
里点名留作干净靶的三个之一(另两个 tn36 / su15), 在 `bench.py` 的课程表里
排在 ft09 之后、r11l 之前。元数据: `tags=['keyboard_click']`, 8 关,
人类基准 `[18,28,18,19,31,23,58,18]`, 可用动作 **`[5,6,7]`**。

动作空间是选它的主要理由: **一个方向键都没有**。前五局要么靠 1-4 的移动做
BFS(ls20/tr87), 要么是纯点击(ft09), sb26 的 A5/A7 + 点击是没碰过的组合。

## 二、harness 裸跑: 0/8, L1 就卡死

`OPERATION_MODE=OFFLINE uv run python blind_sc25.py sb26`, 零人工介入, 350 秒:

```
[ReAct] 实体 4 个, 动作预算 64(单键=64(GAME_OVER))
[ReAct] 因果目标假设 12 条, 首选 region_match((56,61,17,46) 要等于 (0,5,16,45)) 开局 h=174
[Plan] BFS(语义掩码 181 格)   未解出(超时 22.5s) 扩展 445 节点
[Plan] BFS(最短)              未解出(超时 45.0s) 扩展 868 节点
[Plan] [factored] 1 个槽, 独立动作 1 个, **无效 19**
[Plan] [model] 24 个动作: 可用 0 / 状态相关 0 / 无效果 0 / **样本不足 24**
[Plan] 真机最佳优先            未解出(超时 120s, 最好 h=160)  最深 25 层
✗ L1: 0 步 (人类 18) 349.6s
```

**值得记的是: 它的目标假设其实猜得不错。** `region_match((56,61,...) 要等于
(0,5,...))` = "把底下那排弄成跟顶上那排一样", 方向大体是对的。死在两件事上:

1. **20 个动作里 19 个"无效"** —— 于是搜索没有可用的转移, h 从 174 只挪到 160。
2. **`[model]` 24 个动作全部"样本不足"** —— 动力学一条都没学到。

两条都是同一个根因的表象: 这个游戏的动作**单独按没有任何效果**, 必须成对。

## 三、机制是怎么问出来的(四次探测, 每次只问一件事)

### ① 先排除"滞后语义"这个已知陷阱

sc25 的教训是 `perform_action` 只入缓冲、下一步才结算, 单步 diff 看到的是
上一个动作的效果。所以第一件事是用"走两次"重测一遍
([`diag_sb26.py`](../diag_sb26.py)), 结论: **sb26 不滞后**, 单步就生效。
裸跑报的"19 个无效"不是这个陷阱造成的假象。

同一跑里问出了三条硬事实:

- `A5` 只改 1 格 —— 第 53 行那条 64 格长条的最右端。连按 64 次 GAME_OVER,
  所以那是**动作预算条**。
- `A7` 不管怎么按都没有任何变化。
- 点底部四个色块, 每个改 20 格(块周围出现高亮框); **再点同一块又变回去** ——
  典型的选中/取消开关。点顶部框、点面板、点背景, 全都毫无反应。

### ② 否掉"交换"

既然能选中, 最自然的猜测是选 A 再点 B = 交换两块
([`diag_sb26_pair.py`](../diag_sb26_pair.py))。**否掉了**: 六种组合走完,
底部四块颜色一格没动, 改动量始终是 20 格 —— 点第二块只是把高亮挪过去,
是排他性选中。

### ③ 否掉"选中后用键盘操作它"

[`diag_sb26_commit.py`](../diag_sb26_commit.py): 选中后按 A5, 只消耗一格预算
并清掉选中; 按 A7 仍然什么都不发生。**底部四块自始至终没变过** —— 这时才该
怀疑"底部是要重排的对象"这个前提本身。

### ④ 换前提: 底部是调色板, 不是答案区

改问"选中后点面板会怎样"([`diag_sb26_paint.py`](../diag_sb26_paint.py)):
改动 33 格, 并且消耗预算。渲染出来看
([`render_sb26.py`](../render_sb26.py))才看清: **零件从底部消失, 出现在面板
的空槽上**。底部是零件盘, 面板是摆放区, 顶部那排空心框是要摆成的顺序。

L1 到此就解了: 四次"选零件 → 点槽" + 一次 A5 提交 = 9 步, 人类 18。
**A5 不是没用的计数器, 是提交键。**

## 四、真正的题眼: 这游戏在考"把序列因式分解成程序"

L1 的模型(顶部顺序 = 面板顺序)在 L2 就不够用了, 而且每加一关就要改一次前提。
四次修正之后才收敛到正确的语义:

| 关卡 | 新出现的东西 | 前一版模型错在哪 |
| --- | --- | --- |
| L2 | 面板里预先摆着一个零件, 用一根同色管子向下引出**子面板** | "顶部第 i 个目标配第 i 个空槽"串位; 正解是 DFS 前序 |
| L3 | 两个子面板**并排**, 各自被一个零件引出; 没有管子 | 靠"管子"认父子关系不成立 |
| L4 | 容器**还在盘里**, 子面板已经画出来但父面板一个零件都没摆 | 靠"图上的连线"猜锚点不成立 |
| L5 | 目标 9 项, 盘里只有 8 个零件, 且有**两个**同色空心框 | "一个槽出一项"不成立 |
| L8 | 两个面板**互相调用**, 目标是 12 项的周期串 | "展开必须终止"不成立 |

最终模型(`solve_sb26_all.py` 的模块 docstring 就是它):

- 顶部那排空心框 = **展开后**的输出序列, 不是面板的直接映射
- 每个带框面板 = 一段程序, 里面的小标记是空槽
- 盘里的零件看**实心还是空心**分两类:
  - **实心** = 内容, 往输出流里贡献自己这一个颜色
  - **空心** = 对同色子面板的**一次调用**, 展开成那个面板的全部内容
- 同一个子面板可以被调用多次, 但只需要填一次 —— L5 就是这么用 8 个零件
  产出 9 项的: 父面板 `[6,@,@,11,15]` + `@` 子面板 `[14,8,8]`
- **输出流可以是无限的**。L8 两个面板互相调用, 展开成周期串
  `8,11,12,9,14,15,...`, 顶部两行共 12 个框就是**输出缓冲区**, 填满即算对

于是求解 = 在"槽数 = 零件数"的约束下枚举摆法, 跑一遍输出流取前 N 项跟目标
对账。八关最大规模是 9 个零件(含重复色), 直接回溯搜, 毫秒级。

## 五、五个感知层的坑(全都实测踩过, 每个都值一次失败)

这些不是实现细节 —— 它们是"从像素认结构"这件事的真实难度:

1. **进度条要取最下面那条满行**。L5 起顶部目标带的底色也铺满整行, 从上往下
   找会把目标带当成进度条, 整个场景全读歪。
2. **面板边框要按整行"格数"判, 不能按最长连续段**。L2 的子面板管子从父面板
   下边框穿过去, 把那条横线打断成 16+10, 按最长段判直接漏掉父面板。
3. **边框要成对配, 不能取 min/max**。L5 的目标带里也有同色空心框, 取
   min/max 会把面板上边界拉到第 1 行。
4. **左边框连通率阈值 0.9, 不能是 0.5**。L5 里"目标带上边(第1行) + 面板
   下边(第27行)"这一对的列范围**恰好相同**, 左边框连通率 0.56, 0.5 的阈值
   就放它过了 —— 一个纯属巧合的假阳性。
5. **排序要按上沿做行聚类, 不能按平均 y**。引出子面板的零件拖着一条管子,
   平均 y 会被拽到同排空槽的后面, DFS 退化成阅读序, L2 直接不过关。

## 六、这一局说明了什么

**harness 裸跑失败得很"体面"** —— 它的目标假设方向是对的, 死在动力学上:
单独按任何一个动作都没有效果, 于是它学不到任何转移, 20 个动作里 19 个被判
"无效", 搜索没有可用的边。**它缺的不是预算, 是"动作要成对才有意义"这个先验。**
`[model] 样本不足 24` 这一行就是它自己报出来的诊断, 只是没人接着往下问。

**而人工介入解决的也不是搜索问题。** 全程没搜过任何状态空间: 四次探测问清
机制, 之后是纯粹的结构识别 + 一个毫秒级的回溯。这跟 sc25 那种"读源码破译 +
搜索"是两类活。sb26 的难点 100% 在**表征**: 一旦认出"面板是程序、空心件是
调用", 求解本身是平凡的。

这也印证了 ls20 那条老结论的另一面: **表征墙不是搜索墙**。之前是搜索搜不动
因为状态表征不对; 这次是根本不需要搜索, 因为难度全在把画面读成正确的抽象。
harness 目前只会"找目标 + 搜路径", 没有任何机制去假设"画面上这堆东西是一个
可展开的结构"。这是它在 sb26 上零分的真正原因, 加多少预算都不会变。
