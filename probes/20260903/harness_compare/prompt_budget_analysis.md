# 两套 harness 的上下文预算解剖（09-03，冒烟局 vc33 的请求日志）

数据源：`son_runs/20260903_210104_smoke-son-vc33/requests.jsonl`（53 次请求）与
`duck_runs/20260903_210603_smoke-duck-vc33/requests.jsonl`（43 次请求）。同模型、同局、同 240 秒闸刀。

## 一次请求的输入构成（字符数，按角色）

| 角色 | Son 侧 均值/次 | 旧版 均值/次 | 差 |
|---|---|---|---|
| user | 4,770 | 25,537 | 旧版多 20,767 |
| tool（工具返回） | 15,764 | 23,456 | 旧版多 7,692 |

一次请求里的消息条数：Son 均 51 条，旧版均 46 条。旧版消息更少但更长。

## 差距的第一来源：每轮重复的指令块

每一轮的用户消息里，除了状态行（执行了什么动作、第几步第几关、当前合法动作），
后面都跟一段固定的操作说明。这段说明在两套里的长度是：

| | 首轮 | 之后每轮 |
|---|---|---|
| Son | 456 | 582 |
| 旧版 | 2,747 | 2,856 |

一次请求的上下文里带着 9 到 10 轮历史，所以这一项就摊出约 2 万 3 千字符的差距，
占总差距 31,272 的四分之三。旧版每轮重复的内容包括工具签名、不要打印整块棋盘、
怎么比较前后帧、必须给出修订后的世界模型这些话，Son 把它们压成三行，其余留在系统提示词里说一次。

## 差距的第二来源：系统提示词整体重写

两边的系统提示词都是 6 个小节，标题一样，内容 Son 全部改写成压缩版：

| 小节 | Son | 旧版 |
|---|---|---|
| 开场 | 56 | 56 |
| Game overview | 991 | 991 |
| Runtime variables | 2,164 | 4,150 |
| Visual-game guidance | 2,031 | 2,031 |
| Python tool guidance | 1,725 | 3,814 |
| Tool session rules | 776 | 1,301 |

Runtime variables 一节旧版 26 行、Son 9 行，讲的是同一批运行时变量，Son 把一个变量一行改成一行讲三个变量。
Python tool guidance 一节旧版 23 行、Son 7 行。Tool session rules 旧版 7 行、Son 3 行。
两个完全没动的小节是 Game overview 和 Visual-game guidance，逐字一致。

Son 在 Runtime variables 里加了旧版没有的三行，讲 `last_animation` 和自动故事板，
这是他那 1300 行动画感知的说明书。所以他一边砍一边加，净结果还是短了 4,600 字符。

内容上唯一值得注意的取舍：旧版有一条 IMPORTANT 明写「让 agent 走到目标时，写 BFS 这类显式搜索更稳」，
Son 把它压进一句「机制搞清楚之后用打分器或 BFS 最短路搜索」，语气从必须降到建议。

## 差距的第三来源：工具返回更短

工具返回的单条均长：Son 756 字符，旧版 1,293 字符。两边的输出上限配置都是 1024 token，
所以这不是截断口径的差别，是提示词里对「打印什么」的要求不同导致模型自己打得更省。

## 待验证

以上都是上下文预算的账，不是成绩的账。冒烟这一局旧版过了 1 关、Son 0 关，与线上排名相反，
样本太小不能作结论。五局三种子的正式跑正在进行，出数后再谈两者的关系。

## 补充一：对照的干净程度（09-03 核过）

旧版那棵树里有我们八月底加的六个开关（第一关探测、winframe 记录、归因表、持久函数、
棋盘进上下文、任务书跨关先验），全部默认关闭，跑法脚本里也没有导出任何一个。
所以这次比的是 Tufa 公开版对 Son 版，我们自己的改动不参与。
`LEVEL_PRIOR_LINE` 由 `DUCK_TASKBOOK` 控制且只在过关瞬间触发，本次未触发。

## 补充二：Son 的动画感知层在这五局上基本没干活

他那 1300 行动画感知，在主跑的五局第一遍里的实际表现：

| 局 | 唯一工具返回数 | 提到 animation 的 | 出现自动故事板的 |
|---|---|---|---|
| ft09 | 55 | 2 | 0 |
| ls20 | 158 | 1 | 0 |
| r11l | 156 | 20 | 0 |
| sc25 | 125 | 3 | 0 |
| vc33 | 91 | 15 | 0 |

自动故事板一次都没有出现在给模型的消息里（用户消息里 0 次，工具返回里 0 次）。
那些提到 animation 的工具返回，内容是动作结果字典里顺带的动画统计字段
（`animation_frame_count`、`animation_changed_frame_count`、`animation_outlier` 等），
以及模型自己打印的 `Animation info: total_frames 3, changed_frames 2, regions: []`。
`regions` 一直是空列表。

也就是说这一层在算，但在这五局上算不出可报告的运动，自动故事板的触发条件没被满足。
系统提示词里为它写的三行说明每轮都在花上下文，收益为零。
这与 09-03 解剖报告里「跨局管家整场空转」是同一类现象：机制在，触发不了。
线上 Flash-Next 那一跑是否也这样，需要另外查那 22 份 prompt 快照才能说。
