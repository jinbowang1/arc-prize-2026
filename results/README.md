超时阈值、搜索随机性给出不同数字。存档是为了让论文和 README 里引用的每个数字
都能回溯到一条原始记录。

日志全部是脚本 stdout 直接重定向,未经编辑。扫描过凭据(api key / token / 工号 / 邮箱),
0 命中。`environment_files/`(官方游戏源码)仍不入库,重跑需先用 SDK 自行下载。

### 关于末行的 `[verify] ... 未通关`

三个 harness 日志末行都是 `[verify] 全新环境重放 N 步: 未通关 — 通关 X/6`。
这不是重放失败。`harness/run.py:302` 的 `verify_replay` 返回值判据是
`obs.level >= obs.win_levels`,即**整个游戏 6 关全通**才记 True;
跑测只跑了前 2~3 关,自然到不了 6/6。

重放本身是对得上的:cd82 重放 11 步(= L1 的 5 步 + L2 的 6 步)后 `通关 2/6`,
r11l 重放 3 步后 `通关 1/6`,与各自跑测声称的关卡数一致。
这一步存在的意义是防分段解拼接时的边界重复(ls20 L6 踩过,见 `verify_replay` docstring)。

### 🚨这一批最该记住的一条:秒预算让 A/B 对照失效

`canvas_reverted.log` 与 `canvas_baseline_f846d17.log` 跑的是**等价代码**(采集阶段逐行
相同),端到端却一个 13 步差 12 格、一个 9 步差 22 格 —— 差别来自重采那步有没有被
**墙钟**截断,而那取决于当时机器多忙。

而这两个数字本来分别记在 fdf5626 和 f846d17 两次提交上,被当成了两次改动各自的
效果。**判据挂在端到端结果上是对的,但端到端结果本身必须先可复现。**
预算已改成确定性的扩展次数(`canvas.Budget`),墙钟只当安全阀且触发即在日志里
声明"本次不可复现"。

⚠️**确定性验收只做了一半**:两跑在采集与抽象层阶段输出逐字相同,执行阶段的第二跑
被手工中止(机器过热),尚无完整的两跑逐字比对。补跑之前,这条改动只算"接线正确、
行为符合预期"。

### 另一条:差 12 格纹丝不动

`canvas_reverted.log`(118 笔) 与 `canvas_budget_expansions.log`(135 笔) 多采了 17 支笔、
预算机制整个换掉,"最好差 12"一格没动;fdf5626 当时记的也是 12。按本项目判据
——**换搜索策略而结论数字纹丝不动,八成是表征缺了自由度** —— 差 12 应是表征给的地板。
与已定位的病灶一致:构型图非强连通,而规划没把"相邻两笔要走得过去"当硬约束,
所以不是笔不够,是第 4 笔走不过去。
