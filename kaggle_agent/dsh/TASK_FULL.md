你在玩一个 64x64 网格解谜游戏(颜色索引0-15)。没有说明书, 规则要自己从实验里归纳。
目标: 让 level 上升, 尽快过关(现在 level 0)。

接口(本地HTTP, 用 curl):
- curl -s 'http://127.0.0.1:18999/state'  当前局面: 渲染图+连通块摘要+颜色计数账本
- curl -s 'http://127.0.0.1:18999/act?a=6&x=40&y=24'  执行动作: a=6是点击(x=列,y=行); a=1..5是按键
- curl -s 'http://127.0.0.1:18999/grid'  裸grid(JSON), 可写python脚本细分析

规则提示(前人经验):
- 可用动作看 /state 的返回; 点击型游戏的有效目标是物体(连通块), 别扫坐标; 键盘型游戏 a=1..4 常是方向键(上下左右), 先各按一次看效果。
- 每次 act 都消耗预算(共150), 省着用; act 返回"对象级diff"(什么颜色的东西从哪消失/出现在哪, 标注疑似整体移动)。
- 有的格子每步自己变(计数器), /state 会提示, 别当机制。
- 过关条件常见四型: ①答案区逐格等于题面 ②某色数量追平另一色 ③某色清零 ④物体到达特定位置。
- 锁定一个工作假设推进; 假设达成却没过关=假设错了, 立即换。
- 乱点可能死(死了会重置回本关起点), act 返回里会说。

开始吧: 先看 /state, 探测几个连通块目标的点击效果, 归纳机制, 然后用最少步数过关。
过关后(act返回level_up)继续打下一关, 直到预算用尽。

【背景知识】你玩的是人类设计的小型解谜游戏: 一定能通关、不会太难。
老玩家经验, 先对号入座判断种类再按打法行动; 种类只是猜测, 以实际反馈为准。

常见种类与打法:
A 复制图案: 题面+答案区并排 → 弄清"笔"是什么(大笔/小笔/换色/选零件+放置),
  从题面反推笔画; 注意后涂盖先涂。⭐带花纹的 3x3 图案往往就是它**周围邻域**
  应该填成的蓝图(标记语义如: 0→填中心色, 2→填另一色, 3→不填)。
B 导航开锁: ⭐识别特征=按方向键时有一个约5x5的色块整体移动——那就是"你"。
  屏幕角落常有小面板显示你当前的形状/颜色; 某个房间的显示屏展示目标形状。
  打法: 踩地图上的机关格(旋转器/变形器/调色格)把自己变成目标的形状**和**颜色,
  然后走进那个房间。⚠️走路耗能量(有能量条), 耗尽会被传送回起点=前功尽弃,
  所以**禁止漫游**: 摸清每个按键效果后, 先在脑内规划完整路线再走;
  沿途绕开会改变你形状/颜色的格子(拿到目标状态后被改掉=白干)。
C 推箱子: 可动块+插槽 → 只能推不能拉, 别推进死角。
D 点灯开关: 点一格翻一片 → 先摸清翻转模式, 想好该点的集合再动手。
E 词典翻译: 成对样例+待填区 → 从样例归纳映射, 循环键换候选填进去, 全对自动过关。
F 画符施法: 小画布+图案提示+角色+出口 → 画对图案是放技能, 过关要角色走进出口。
G 连锁消除/收集: 点关键位置引发大连锁, 或把散落图案收进槽位 → 优先点中心/缺口/对称点。
都不像: 找答案区和题面, 每个动作试一次记效果, 把"与题面的差距"做小。
